# Phase 1 — Engine, ledger, lock, proof

No UI and no notices in this phase. Input is the frozen fixtures and the goldens; output is a pure engine that agrees with the oracle, a database whose one hot row is locked per bid and verified against its ledger, a close job that settles, and a contention proof with a measurement. The exit bar is "the TypeScript engine and the database replay both reproduce `expected_bids.csv` and `expected_lots.csv` exactly, the barrier test passes at N = 50 with zero invariant failures, and `docs/LOAD.md` exists with its hardware line".

Scripts in CLAUDE.md exist as stubs that exit 0: `auction:eval` prints `0 lots`, `auction:verify`, `auction:close`, `fixtures:check`, `rules:lint`, `load:bids`. Scope banner verbatim in README. Model pin in `.claude/settings.json` merged with whatever the template put there. CI workflow (ported from LoanBook's: Postgres 17 service with `TZ=America/Chicago`, `npm ci`, lint, typecheck, migrate deploy, `fixtures:check`, `rules:lint`, `auction:verify`, vitest, e2e) with no secrets. Reuse check run and recorded in `docs/decisions.md`. *Acceptance:* `npm run foundation:drift` and `npm test` pass before any Gavel code exists; every command runs; `git ls-files | grep -iE "\.env$|secret|credential|\.pem$|\.key$"` prints only `.env.example`.

- [x] **1.4 Rules loader and lint.** `src/auction/engine/rules.ts` loads `rules/auction.v1.json` with a small hand-written validator (bands contiguous from 0, open-ended last band, non-decreasing positive increments, defaults present and integer, closed outcome lists); exposes `rulesHash`. `rules:lint` fails on a schema miss, on a hash that differs from D-23, and on `prisma`, `@/core`, `@/app`, `Date.now`, `new Date`, `Math.random`, `process.env`, `fetch`, `setTimeout` under `src/auction/engine/` (the service files beside it are allowed Prisma and `@/core/clock`). *Acceptance:* `rules:lint` OK; a test changes one byte of a copy of the rules and the hash check fails; a test with overlapping bands is refused.

Integer cents and ms only; a non-integer throws before anything else. *Acceptance:* GB-00..GB-14, GB-17, GB-19, GB-22, GB-23 pass with exact values; `rules:lint` OK.
- [x] **1.6 Engine: replay, fold, settle; `auction:eval` (engine half).** `replay(lot, submissions)` with the idempotency rule (D-17), `fold(lot, rows)` refusing a seq gap or an outcome that disagrees, `settle(lot, state, nowMs)`, `lotStatus`. `auction:eval` reads `fixtures/auctions.json` and `submissions.jsonl`, replays every lot through the engine, writes the §11 columns, diffs against `expected_bids.csv` and `expected_lots.csv`, prints the brief §10 table and the rules hash, exits non-zero on any difference. *Acceptance:* GB-15, GB-16, GB-18, GB-20, GB-21 pass; `auction:eval` reproduces both expected files column for column (220 submissions, 36 lots); a determinism test replays twice and diffs nothing.
- [ ] **1.7 Schema and migrations.** `prisma/schema/gavel.prisma`: `Auction` (org, name, `softCloseWindowSeconds`, `maxExtensionSeconds`, `buyerPremiumBps`, `opensAt`), `Lot` (auction, number, title, description, imageUrl, consignor text, `startCents`, `reserveCents?`, `scheduledEnd`), `LotState` (1:1 with `Lot`, the D-16 columns, created in the same transaction as the lot), `Bidder` (user × org, paddle, status), `Bid` (D-14 columns; unique `(lotId, seq)`; unique `(lotId, bidderId, idempotencyKey)`), `Settlement` (D-22 columns, `rulesHash`, unique `lotId`). Hand-written SQL in the migration: append-only triggers on `Bid` and `Settlement` (UPDATE/DELETE raise), DELETE refused on `LotState`, CHECK constraints `startCents > 0`, `reserveCents IS NULL OR reserveCents >= startCents`, `scheduledEnd > opensAt`, `maxCents > 0`, `priceAfterCents >= priceBeforeCents`, `closesAtAfter >= closesAtBefore`, `seq >= 1`. Every table carries `orgId` and is read through the tenancy layer. *Acceptance:* a migration test applies from scratch on an empty database; UPDATE and DELETE on a `Bid` row fail with the trigger's message; `foundation:drift` clean.
- [ ] **1.8 `placeBid` under the lock.** `src/auction/place-bid.ts`: boundary checks (integer, lot in org, bidder ACTIVE, key present) outside the transaction; then one interactive transaction with `timeout` above the lock wait: `SET LOCAL lock_timeout = '5000ms'`, `SELECT … FROM "LotState" WHERE "lotId" = $1 FOR UPDATE`, `now()` from `@/core/clock` (or an injected `now` for tests), the idempotency read, `applyBid`, the `Bid` insert, the `LotState` update. Errors mapped: 55P03 → `BID_TIMED_OUT` (retryable, same key); 23505 on the idempotency index → treated as a replay re-read (defence in depth); `IDEMPOTENCY_MISMATCH`. Response: outcome, price, next minimum, `youLead`, `closesAt`, seq, `replayed`; never a max, a reserve or another bidder's id. *Acceptance:* a sequential test drives the REPLAY and OWN_RAISE lots through `placeBid` with a scripted clock and matches `expected_bids.csv`; a test holds the lock on a raw connection for 6 s and asserts `BID_TIMED_OUT` (not a Prisma timeout) and no row; a test inserts a duplicate key through a raw connection and asserts the mapped error; `placedAt` of a bid that waited behind a 2 s lock hold is after the release, not before.
- [ ] **1.9 Database replay, close, verify.** `auction:eval` (database half): truncate, load `fixtures/auctions.json`, drive every submission through `placeBid` in arrival order with the clock pinned to each `placed_at_ms`, then `auction:close --as-of` the §10 `as_of`, then diff the `Bid` and `Settlement` tables against the expected files. `auction:verify`: V1–V9 in `src/auction/verify-sql.ts` over every lot, first failure named, non-zero exit. *Acceptance:* the database replay matches both expected files; `auction:verify` OK after it; a test that corrupts `LotState.priceCents` through a raw connection makes V1 fail naming the lot; a test that inserts a `Settlement` for an open lot makes V8 fail.
- [ ] **1.10 The barrier test.** `tests/contention/barrier.test.ts` per D-18 and brief §8, for N in {2, 10, 25, 50} (CI: 25 via an env var, O-10): a lot with `closesAt = T`, the clock pinned to `T − 1000`, N raw `pg` clients queued on the `LotState` row behind a holder, released together; assert the §8 list, then the resend pass, then `auction:verify`, then `pg_stat_activity` count equals the pre-test count. Header states `fileParallelism: false` and why (the `pg_locks` count is database-wide). Also 1c's cousin: one writer rolls back after the lock and the next seq has no gap. *Acceptance:* green at N = 50 locally three runs in a row with the same outcome table; a deliberately broken `placeBid` (clock read before the lock) is caught by V6 on the 2 s-hold test from 1.8, proved on a throwaway branch.
- [ ] **1.11 Load script and `docs/LOAD.md`.** `scripts/load-bids.ts` per D-19: M writers (default 200) over L lots (default 4) whose `scheduledEnd` is 10 s out, real clock, real `placeBid`, each writer bidding until its lot closes with a fresh key per attempt; prints outcome counts, bids/sec, p50/p95/p99 ms around `placeBid`, max `wait_event` duration seen in `pg_stat_activity`, then the hardware block, and writes `docs/LOAD.md`; runs `auction:verify` last and fails if it fails. *Acceptance:* `docs/LOAD.md` committed from the first run on the Mac with every number beside its hardware line; `NEXT.md` quotes the line, not a rounded version of it.
- [ ] **1.12 CI gate and the red/green proof.** CI runs `rules:lint`, `fixtures:check`, migrations, `auction:eval`, `auction:verify`, vitest including the barrier test at N = 25, with a float lint over `src/auction/engine/` (no `/`, `Math.round`, `toFixed`, `parseFloat` in a cents, bps or ms path). Prove it on a throwaway branch by changing `increment_cents` of the first band to 150 (then revert): `rules:lint` and `auction:eval` must both go red. *Acceptance:* the red run and the green run are both linked in `NEXT.md`.

**Exit criteria:** GB-00..GB-23 pass in TypeScript; `auction:eval` reproduces both expected files from the engine and from the database; `auction:verify` and `fixtures:check` and `rules:lint` OK; the barrier test is green at N = 50 locally and N = 25 in CI; `docs/LOAD.md` exists with its hardware line; no forbidden import or float under `src/auction/engine/`; CI enforces the gate.
